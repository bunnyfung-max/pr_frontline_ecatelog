# 產品及 Sales Kit 購物連結

## CMS 設定位置

| 項目 | 編輯位置 | 儲存欄位 |
| --- | --- | --- |
| 產品自在購 | 產品索引 → 選擇產品 → 自在購產品連結 | Product.storeUrl |
| 產品 eShop | 產品索引 → 選擇產品 → eShop 產品連結 | Product.url（保留現有欄位及資料） |
| Sales Kit / 展示內容自在購 | 內容編輯 → 本份內容 / Sales Kit 專屬購物連結 | Content.storeUrl |
| Sales Kit / 展示內容 eShop | 同上 | Content.eshopUrl |

以上均選填、最多 2,000 字元，只接受 HTTPS。既有場景及 Bundle Offer 連結維持原有管理方式。

## 展示規則

- 購物功能列先顯示「本份內容」連結，再顯示在該份內容勾選的相關產品，各產品分別使用自己的兩條連結。
- Sales Kit 的連結不會覆蓋產品連結；產品也不會繼承 Sales Kit 或全站共用連結。
- 只顯示已填寫且有效的購物按鈕；兩條均未填時顯示「購物連結待設定」。
- 開啟新分頁，保留原有展示頁碼；未關聯的產品不會出現在該份內容。
- 既有 Bundle Offer 清單、啟停及有效日期不變。

## 儲存及相容性

- 沿用管理員 API 驗證、內容版本檢查、Postgres RLS 及現有本機 JSON 儲存。
- Supabase 的 catalog_entries.payload 是 JSONB，新增欄位不需要更改資料表或搬移資料。
- 舊產品 url 繼續作 eShop 用途；舊資料缺少新欄位視作未設定，在下次儲存時補上空值。
- 舊 settings 記錄保留，不刪除資料；但前端不再讀取它作購物連結，CMS 亦移除共用自在購設定入口。
- 生產環境仍需管理員填寫及驗證各個正式目的地，程式不會自行推算產品 URL。

## 本次驗證

- 產品 / 內容欄位及預覽實際瀏覽器檢查；預覽用的 example.com 網址沒有儲存、發布或開啟。
- 自在購與 eShop 連結分離、產品隔離、缺漏欄位相容、清空欄位、HTTPS 驗證及不採用共用網址的自動測試。
- Postgres JSONB 及 RLS 測試證實兩類資料的專屬連結可正確儲存並由員工角色讀取。此為本機 Postgres 模擬，非已連接 Supabase 的端到端驗收。
