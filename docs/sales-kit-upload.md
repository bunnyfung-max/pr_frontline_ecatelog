# New Housing Sales Kit 上載與展示

## CMS 規格

在 New Housing 或其子目錄選擇上載／編輯圖片 Sales Kit，顯示 5 個圖片位置：

1. 平面圖 Floor Plan：發布時必填。
2. 效果圖：發布時必填。
3. 產品列表（一）：發布時必填。
4. 產品列表（二）：發布時必填。
5. 補充圖片：無固定用途，選填。

每個位置獨立上載、替換及移除，只接受 JPG/PNG/WebP。移除只清空該位置，不把後面的圖向前推。未齊頭四張可以存草稿，不能發布；第 5 張毋須填滿。

「其他檔案」可多選加入圖片、PDF、MP4、WebM；只在額外檔案區內上下排序。每檔 50 MB，保留原來每內容最多 40 個檔案位置的限制，即 5 個標準位置加最多 35 個額外檔案。批次中途失敗時已成功上載的項目仍留在表格，方便繼續。

上載目的地、相關產品、個別自在購/eShop 連結、搜尋關鍵字及封面設定不變。一般 POP 圖片及獨立 PDF、影片、外部連結維持原來上載方式。

## 展示規則

- 按 CMS 儲存次序：平面圖 → 效果圖 → 產品列表（一）→ 產品列表（二）→ 選填補充圖 → 額外檔案。
- 空白選填位置不產生空白頁；草稿預覽亦會略過尚未上載的位置。
- PDF 按原頁次展開，完成後才到下一份附件，不會將 PDF 或影片重新分類到末尾。
- 橫向最多兩頁圖片/PDF；直向一頁。影片獨立展示，不會與旁邊圖片組成雙頁；上一頁／下一頁不跳過項目。
- 切走影片時卸載播放器，避免繼續播放；PDF 載入失敗仍保留錯誤位置，可重試或翻到後面附件。
- 頁碼按實際展示頁計算，包含 PDF 的各頁，因此可能多於上載檔案數量。

## 儲存及兼容

`Content.salesKit?: boolean` 標示此格式，沿用 `type: image` 和有序 `files` 陣列。第 0–4 位保留圖片位置（可以空字串），第 5 位起是額外附件。API 驗證標準位置格式、發布所需頭四張，以及附件白名單；New Housing 新增圖片內容須使用 Sales Kit 格式。

所有引用仍存放在 `files`，沿用資產 API 和 Supabase 私人 Storage 的引用驗證；不增加公開路徑、外部檔案網址或額外 schema migration。Postgres JSONB/RLS 模擬已驗證影片/PDF 只會隨已發布 Kit 開放，Kit 下架後無其他引用的附件不可供 frontline 取閱。

既有內容不自動更改。舊 New Housing 圖片 Kit 開啟編輯時，在表格中依舊次序帶入並補出空欄位，提示管理員核對用途；未儲存不改動原記錄。重新發布須補齊頭四張。檔案不自動覆寫或刪除，取消編輯會保留原內容；未引用上載素材延續原來人工清理政策。

## 本機驗證（2026-09-19）

- 28 項 unit/component/Postgres 測試通過；TypeScript 及 production build 通過。
- `scripts/check-sales-kit.mjs` 以合成圖片、3 頁 PDF、1 秒單影格 WebM 測試實際本機上載、資產取回、草稿、發布限制、發布／下架及讀回次序。新增一份已下架 QA fixture，沒有修改原有內容或正式素材。
- IAB 檢查 5 個欄位、移除效果圖後其餘位置不變且禁止發布、附件上下移動、預覽的頭四頁、PDF 第 5–7 頁、影片第 8 頁及末張圖第 9 頁、上一頁；實際 PDF canvas 和影片 metadata 成功載入，影片控制可用。
- 768×1024 直向預覽一次一頁，無橫向溢出；完成後還原 1280×720。瀏覽器沒有 error/warn。
- 圖片：`qa/sales-kit-pdf-spread.png`、`qa/sales-kit-video.png`、`qa/sales-kit-portrait.png`、`qa/sales-kit-upload.png`。合成色塊只用於核對序列，非正式產品圖片。
- Browser E2E source 已更新四個圖片位置的上載流程；此輪沒有重跑 Playwright CLI 或透過原生檔案選擇器上載。此轮真實檔案上載由本機 API 驗證。
- Hosted Supabase/Vercel、公司真實大檔案和 iPad Safari 尚待接駁及設備驗收。
